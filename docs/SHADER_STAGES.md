# Restricted graphics shader stages (v0.23.0)

This is independent fixture research, not an Xbox shader ABI. All instructions are decoded from 32-bit words, with literal and 64-bit instruction bounds checks. Supported VOP1 MOV_B32 and VOP2 ADD/SUB/SUBREV/MUL/MIN/MAX_F32, bitwise/shift operations, and six unsigned integer operations (ADD/SUB/SUBREV_NC_U32, MIN/MAX_U32, MUL_U32_U24) use VGPR operands, literal DWORDs and the supported inline constant selectors. Integer operations use raw 32-bit representations and unsigned arithmetic; shifts mask the count, and multiplication masks operands to 24 bits. The fixed register ABI and limited float edge-case validation remain unchanged. EXP accepts uncompressed full masks only: vertex PARAM0 then POS0 with DONE; pixel MRT0 with DONE/VM. The fixed vertex ABI maps v0..4 to host position x,y,z and UV, and exports four clip coordinates and four attributes. The fixed pixel ABI maps v0..1 to already-interpolated UV. HLSL uses perspective-correct TEXCOORD0 interpolation; no guest interpolation instructions are decoded. No EXEC, compressed exports, additional render targets, arbitrary descriptor heaps or shader-stage metadata.

MIMG `image_sample_l` accepts only contiguous FP32 2D coordinates and LOD with dmask=15, no additional flags, image SGPR group s[0:7] and sampler s[8:11], interpreted as host t0/s0. LOD must be statically known zero. A single sample per pixel is allowed; all four VGPR outputs are pending until the full VMEM wait. Host fixture uses a 2x2 RGBA8 UNORM texture, point/clamp sampler. The CPU evaluator uses that palette and finite inputs; exceptional FP behaviour and arbitrary texture state are outside the fixture. Other instruction combinations may compile but are not generally validated for exact AMD numerical semantics.

The vertex fixture computes the existing perspective transform with three FP32 operations, exports UV and clip coordinates. The pixel fixture samples the texture and exports blue, green, red, alpha in that order. The GPU test also uses the existing translated compute texture producer, direct-queue wait, descriptor registry, indexed depth test and readback. The CPU pixel oracle checks interior pixels with red/blue swapped; ambiguous raster edges and sampling boundaries are omitted. The GPU command uses built-in fixtures, not user-supplied shader files. CLI decode/emit accept restricted text word streams. HLSL is compiled using D3DCompile VS/PS 5.1 (DXBC), not DXIL; Windows compilation and GPU execution are not tested locally. No new translated graphics PSO disk cache is provided.

Public research references: AMD RDNA2 ISA document 70648 (https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna2-shader-instruction-set-architecture.pdf); LLVM GFX10 public EXP and MIMG encoding examples (https://llvm.googlesource.com/llvm-project/+/refs/heads/users/arichardson/support-highlight-the-whole-directive-in-verifier-errors/llvm/test/MC/Disassembler/AMDGPU/gfx10_mimg.txt and https://llvm.googlesource.com/llvm-project/+/refs/heads/users/arichardson/support-highlight-the-whole-directive-in-verifier-errors/llvm/test/MC/Disassembler/AMDGPU/gfx10_exp.txt). Encodings cross-checked from public examples, not a hardware assembler run. No third-party implementation code incorporated.
