# Persistent multipass and typed binding (v0.52.0)

The renderer is a bounded desktop D3D12 reference, not D3D12.X translation. It serialises calls with a mutex and retains one device, two signatures, four fixed PSOs, queue, monotonic fence and event. The single geometry-keyed slot holds three colour targets, depth/stencil, three readbacks, three descriptor heaps, allocator and list. Colour targets return to render-target state before fence signalling; depth stays depth-write. Every call clears all targets and waits for completion before readback or reuse. Size changes allocate a replacement transactionally while the old completed slot remains valid. The cache is module-local; the CLI and ABI DLL do not share it. No asynchronous overlapping submissions, eviction policy, device-loss recovery or general PSO cache. Recording/submission/readback errors poison the context until process exit.

`Revenge.exe render-pass-gpu-test` now checks the original 768 pixels and 24 extra workloads with 21,504 pixels, including a size change and 23 slot reuses. Every channel must be within one byte of the independent CPU oracle. Timing includes CPU oracle and is not game FPS. Windows execution is pending.

`native_fixed_image` now validates the exact fixture import name, module, slot, image extent and flags using a typed host function before patching the IAT. Eight malformed plans are rejected with unchanged bytes. Existing fixed relocation, two independent mappings, page protections and unwind tests remain. No external executable path, arbitrary loader, dynamic API binding or console execution is added. The focused build includes this test.
