# Continuous translated graphics (v0.27.0)

This additive native ABI v1 extension preserves all five exported functions and the 56-byte `rv_request` layout. `RV_GFX_RUN` (19) accepts a session-owned known-scene package handle, width 320–3840, height 240–2160, duration 1–30 seconds, FPS cap 0 (uncapped) or 1–240, and a writable 56-byte `rv_frame_stats`. Result is the byte count. Invalid dimensions, duration, cap, buffer size and foreign or stale handles are rejected. Linux reports unsupported for valid GPU requests. Capabilities describe compiled backends, not physical devices. Existing `RV_GFX_DRAW` remains unchanged.

A synchronous call holds the session graphics mutex and the global GPU lock. Startup uses the existing translated compute/vertex/pixel path, generates the texture once, verifies the initial framebuffer and retains the GPU device, root signature, PSO, vertex/index buffers, texture and descriptor. A fixed-size RGBA8 color target and depth target are redrawn each iteration with the same indexed command sequence. The viewport shifts horizontally in integer pixels; arrow keys override automatic motion when the window has focus, and the first connected XInput controller's normalized left stick can also override movement. A two-buffer flip-discard swap chain displays the copied GPU frame. The window may stretch the fixed internal render extent.

The command allocator/list, timestamp pair and render targets are reused only after fence completion (one in-flight frame). Each frame reports successful Present calls separately from submissions. Mean GPU draw/copy duration is calculated from direct-queue timestamps; the wall interval excludes setup and final readback, and includes pacing, window messages and fence waits. The cap is a best-effort upper pacing target, not a guaranteed refresh rate. Present calls/s are not physical scanout FPS. The test stops on duration, Escape/window close or safety frame limit; minimized windows skip draws. If no frame is successfully presented, the service fails. The last submitted framebuffer is independently verified using the shifted CPU oracle, then descriptor handles are retired after fence completion. Only initial/final frames are fully checked; other frames are not read back.

Known-scene fixtures only; no arbitrary geometry, general GPU resource ABI, asynchronous command submission, per-frame compute regeneration, cross-process service or Xbox compatibility. Windows execution is unverified in the Linux build environment. The host process must be trusted and must not close a session while calls are active.
