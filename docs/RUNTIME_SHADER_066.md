# v0.66.0 controlled runtime and integer shader validation

The focused Windows validation now builds the independently authored `revenge_runtime_fixture.exe` and launches it in normal and diagnostic modes through the existing supervised Windows process runner. The Windows OS loader, not Revenge, installs the executable static TLS and invokes its callbacks. Eight worker lifecycles check initialised/zero-initialised TLS contents, parent isolation, writable non-executable pages and exception unwinding. MSVC x64 uses a `.CRT$XLB` TLS callback and loader-safe interlocked counters to verify process attach and thread attach/detach. Process detach is not checked. Other compilers do not exercise the explicit callback registration. The launcher reports the child exit status and enforces its existing time limit. No Xbox application loader or guest TLS ABI is implemented.

Six existing compute-fixture VOP2 encodings are now supported by the vertex and pixel stage translator: 11 `v_mul_u32_u24`, 19/20 `v_min_u32`/`v_max_u32`, 37/38/39 `v_add_nc_u32`/`v_sub_nc_u32`/`v_subrev_nc_u32`. The CPU evaluator and HLSL emitter use raw 32-bit integer representations, unsigned wraparound, and 24-bit operand masks. Eight known-answer cases cover these operations. The new resident GPU fixture clamps a sampled channel to 0.25 using unsigned minimum and checks 405 pixels across two extents. The GPU test is Windows-only and must be run on hardware. General compares, condition masks, control flow, wave semantics, arbitrary NaN payloads, denormal preservation, console descriptor ABI and arbitrary shaders remain unsupported or unverified.

Run `Build-And-Test-Revenge.ps1 -FastBuild -BuildJobs 2 -Focused`. Expected with the public Windows GDK configured: 29 focused tests and seven GPU tests. See the portable log for Linux-only results.
