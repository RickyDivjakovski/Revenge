# Integrated fixed loader lifecycle

The existing `native_fixed_image` regression now constructs a second fixed PE entirely from source. No file path or arbitrary executable is accepted. It prepares six DIR64 relocations, checks TLS metadata, writes a reference-only TLS index, binds one known typed host function, sets page protections, flushes the instruction cache, and registers the fixed unwind table on Windows. Native callbacks record their reason and invocation count. Eight sequentially joined workers exercise explicit aligned TLS reference storage and the typed import. A second run injects a worker failure and checks thread detach, process detach and unwind cleanup; seven illegal callback transitions per run must leave the callback counter unchanged. Process detach and unwind deregistration precede mapping destruction. The original independent mapping and malformed binding tests are retained.

The reference TLS index and storage do not modify the OS static TLS vector; guest code does not access them via the platform static TLS ABI. Callback invocation is explicit and only applies to generated code. Linux verifies the native fixture but not Windows unwind registration. No general executable loader, external target execution or Xbox ABI is provided. Existing graphics tests remain unchanged.
