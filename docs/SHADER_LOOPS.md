# Bounded loop and logical wave-mask fixtures

The opt-in `decode_loop` path uses the existing public GFX10.3 flow instruction subset, plus SOP2 `s_add_u32` (unsigned 32-bit sum, SCC carry) and signed 16-bit SOPP branch displacement from the next word. Branches must target instruction starts. Non-buffer programs only: no pending memory dependencies across backedges. Definite assignment is intersected for forward joins; each backward edge must preserve all known definitions at its destination. This conservative validator rejects unreachable instructions and uninitialized SCC. No proof of termination is attempted.

The CPU interpreter enforces a 1,024-instruction budget and throws on exhaustion. Generated HLSL dispatches one instruction per iteration and writes 0xffffffff on exhaustion; this is a diagnostic marker for the known-answer fixture, not a general guest exception ABI. The sample returns id + floor(id/64) + 1, executing 1–64 iterations. The existing forward and buffer paths are unchanged in supported instruction coverage.

The logical wave fixtures use 64-thread groups with two 32-bit group-shared EXEC and VCC words. Wave32 treats each half independently, Wave64 treats both halves as one logical wave. Uniform group barriers separate mask initialization, atomic bit updates and reads. CPU WaveMask reference tests verify the complete mask words and selected writes; an independent direct formula checks all outputs. No hardware wave width is assumed; this is a synthetic compute fixture, not decoding or recompiling EXEC/VCC instructions, native wave intrinsics, or a complete divergence/reconvergence model.

Windows commands use D3DCompile cs_5_1 and the existing 4,096-output known-answer harness. GPU results remain unverified until run on Windows. No console code, resource ABI, texture opcodes, vertex/pixel recompilation or commercial game execution is included in this increment.
